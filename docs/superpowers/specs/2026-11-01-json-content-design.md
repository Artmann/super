# JSON content

The README promises `content.LoadAll<Item>("items")`, validation, schemas and live
reload. This is how they're built, with the calls made along the way.

## What a game sees

- `content.LoadAll<T>(folder)` reads every `.json` file under `content/<folder>`, one
  record per file, and returns a `Catalog<T>`. It reads when called, on the calling
  thread, so a bad file stops the game at load and never mid-tick.
- `Catalog<T>` looks up by id, counts, and enumerates in file path order without
  allocating. The order is fixed, so a seed plays the same whatever the disk returns.
- `ModelRef` fields are written as paths in JSON. `Ref<T>` fields are the id of a record
  in another catalog, looked up with `catalog[reference]`.

## Calls made

- **One record per file, and `T` needs a string `Id`.** The README shows this. Anything
  else is a programming mistake and throws straight away.
- **Validation walks the JSON itself, against System.Text.Json's description of the
  type.** The serializer stops at the first problem and its messages aren't meant for
  people. A walk reports every problem in every file, with real line numbers, in the
  README's words. The serializer still does the actual reading, and only runs on data
  that passed.
- **Strict by default.** Field names are camelCase and exact. Unknown fields, missing
  constructor parameters and nulls in non-nullable fields are all errors. A parameter
  with a default value is optional.
- **`Ref<T>` is checked when both sides are loaded.** Order of `LoadAll` calls doesn't
  matter inside one `Load` or tick. Whatever is still unresolved after `Load`, or at the
  end of a tick, is an error.
- **Model paths are checked only where cooked assets exist.** Assets aren't in git, so a
  fresh checkout or a test run with no `assets/cooked` folder can't check them, and
  skips it rather than failing.
- **The folder is found like `assets/cooked`,** by walking up from the program. Tests can
  replace `IContentFiles`. `Super.Testing` has an in-memory version.
- **Schemas are generated by `JsonSchemaExporter`,** and written to `content/.schemas`
  when a game opens its window from source. Headless runs write nothing. Super never
  edits editor settings. A file links its schema with a `$schema` field, which loading
  ignores, or a project maps a folder in `json.schemas`.
- **Live reload runs only in the interactive window, and only from source.** A shipped
  game has `content` beside the program. A game run from source finds it further up, so
  no flag is needed.
- **A reload is all or nothing.** Everything is read again and swapped at the start of a
  tick. A mistake while the game runs prints to the error stream and keeps the old data,
  since a typo shouldn't end a play session. `catalog.OnChange` tells a game to refresh
  what it copied out.

## Left out

- **Mods.** Nothing loads a second folder yet. The README says so.
- **Saves.** `saves.Write` and `Read` are a separate piece of work.
- **`Vector3` and color fields.** Use numbers or arrays until a game needs more.
- **Unloading.** Nothing in `Content` unloads yet.
