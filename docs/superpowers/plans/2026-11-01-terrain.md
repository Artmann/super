# Procedural Terrain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a Super game build procedural terrain: generated chunk meshes with a game-written layered shader, textures that load and unload while playing, sub-allocated GPU memory, and cascaded sun shadows.

**Architecture:** Rendition gains a `GpuMemory` sub-allocator, destroy and upload queues keyed to the two frames in flight, texture arrays in a third bindless binding, eight parameters plus eight texture slots per material, and a four-layer cascaded shadow map. Super's `Content` names shaders, textures and texture arrays the same way it names models, `GeneratedMesh` carries a `Surface`, and `Super.Terrain.Heightfield` builds seamless chunks. An `examples/Terrain` project streams chunks around a fly camera.

**Tech Stack:** C# / .NET 10, Silk.NET.Vulkan, GLSL compiled by glslc through `src/Shaders.targets`, StbImageSharp, xunit.

**Spec:** `docs/superpowers/specs/2026-11-01-terrain-design.md`

## Global Constraints

- Braces on every control statement. Conventional commits, no Claude authorship.
- The `--check` run of `Rendition.Sample` must still allocate nothing and produce no validation messages; add the destroy queue and cascades to what it exercises.
- `SpinningCubeTests.Running_the_game_allocates_nothing_per_frame` keeps passing.
- GLSL compiles with `-Werror` under `glslc`.
- Everything in `Content` must work with `IContentFiles` in memory, so tests can hand it a PNG encoded with the existing `PngFile` writer.
- Create paths may allocate managed memory. Only the destroy and upload queues, and rendering, must not once steady.
- `Render` allocates no managed memory. Any list that queues work is preallocated or grows only on first use.

## Review Focus

1. Destroying a texture whose slot is in use by the frame still in flight: the slot must not be rewritten until that frame's fence has signalled (Task 2 test: release happens on the second `Render` after `Destroy`, not the first).
2. A texture array whose layers differ in size, kind or mip count: `CreateTextureArray` throws naming the layer (Task 4 test).
3. A material that names a destroyed texture: the white texture draws, nothing crashes (covered by `--check` in Task 7 which destroys a texture then keeps drawing).
4. A surface referencing a ref that was never named, or an unloaded one: `Content.Mesh` throws with the field name; drawing an unloaded model throws with its index (Task 8 tests).
5. Chunks on either side of a border must share border vertices bit-for-bit, including normals, with a height function that isn't grid-aligned (Task 9 test).

Build with `dotnet build Super.slnx -c Release`, test with `dotnet test Super.slnx -c Release --no-build`, and after every renderer task run `dotnet run -c Release --project src/Rendition.Sample -- --check` and expect `0 bytes allocated, 0 validation messages`.

### Task 5: Cascaded shadows

**Files:**
- Modify: `Passes/ShadowPass.cs`, `Passes/FrameUniforms.cs`, `Passes/SceneDraws.cs` (push constants gain `int Cascade`), `Renderer.cs` (`WriteUniforms`, `SelectDraws` per cascade, `DrawnTriangles.Shadows`), `Types.cs` (`ShadowSettings.Cascades`), `Shaders/common.glsl`, `shadow.vert`, `lighting.frag`, `ao.frag`, `src/Super/View.cs`, `src/Super/Rendering/SceneRenderer.cs`, `examples/Reef/ReefGame.cs` (`Shadows(25f, 3)`), `src/Rendition.Sample/Program.cs` (car radius + 2 cascades in `--check`)

**Interfaces:**
- `ShadowPass.Resolution = 2048`, `Layers = 4`; `RenderTarget` becomes a 4-layer `D32Sfloat` image with one array view (for sampling) and four per-layer views (for rendering). `Record(cmd, frameSet, draws[cascade], meshes, cascade)` begins rendering once per layer.
- `FrameUniforms`: `ShadowMatrix` becomes `ShadowMatricesArray ShadowMatrices` (`[InlineArray(4)] Matrix4x4`) plus `Vector4 ShadowRadii`; `common.glsl` `mat4 shadowMatrices[4]; vec4 shadowRadii;`. `lighting.frag` picks the first cascade whose projected xy lies within `[inset, 1-inset]` with `inset = 2 texels`, samples `sampler2DArrayShadow` / `sampler2DArray` with layer; AO and probes use layer 0.
- Cascade i: centre snapped to the texel grid in light space, radius `Radius * 3^i`. `View.Shadows(float radius, int cascades = 1)`.

- [x] **Step 1: Implement and build.** `--check` with two cascades → clean. Screenshot the sample and Reef with `--screenshot` to check shadows still land.
