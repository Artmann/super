# Interface toolkit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real game interfaces in `Super.Ui`: CSS-style layout and boxes, images, scrolling, lists, grids, and complete mouse support, proven by a crafting screen.

**Architecture:** Views stay records over `UiNode`. A new `UiPointer` owns all mouse behavior and is the only route mouse buttons and the wheel take into `Input`, so the interface decides what the game sees before a tick rolls. Rendition gains richer quads and knows nothing of `Super.Ui`.

**Tech Stack:** C# / .NET 10, Vulkan through Silk.NET, GLSL, xUnit, StbImageSharp 2.30.16.

**Spec:** `docs/superpowers/specs/2026-11-01-ui-layout-design.md`

## Global Constraints

- Braces on every control statement. Conventional commits. No Claude authorship lines.
- `Ui` never reads `Input`. Callbacks that change game state run only on a tick.
- Nothing allocates per frame in Rendition's render path.
- Rendition doesn't reference `Super.Ui`.
- Never `git add` `.superpowers/`. Never capture the desktop.
- Only CC0 assets, recorded in `CREDITS.md`.

## Decisions the spec left open

- **Pointer events are a queue.** With a router set, `Input.MouseButtonDown/Up` and `Scrolled` queue events instead of touching the snapshot. `UiPointer.Pump()` drains them, and passes on to the snapshot only what the interface didn't take. This hides a tap completely, which masking reads after the roll can't do, because a tap spreads over two ticks. Without a router, `Input` behaves as today.
- **`Pump` runs twice:** at the top of `GameHost.Tick` before `Input.Roll`, so blocking is decided before a tick sees it, and at the top of `Draw`, for frame rate. It's safe because it drains.
- **Callbacks are looked up on the node's current view at release**, so they're never stale. They run after tick hooks, just before `Game.Update`.
- **Closures make views unequal.** A view holding a fresh lambda is laid out again each frame. Accepted and documented: it costs hundreds of rows' worth of layout at worst.
- **`UiNode` tracks `Mounted`.** The pointer drops a press or drag whose node left the tree.
- **`OverlayQuad.TextureIndex` 0 is the atlas**, anything else is the table index plus one. A zero-width clip rect means no clip, so a default quad stays valid.
- **Images:** `Content.Image(path)` returns a `GameImage` with its size from the file header. `UiTree` records which quads use which image, and `SceneRenderer` fills in the index before drawing.
- **Tooltip delay counts ticks** (0.5 s), so it repeats. Scrollbar 10 px with a gutter reserved only on overflow. Drag threshold 4 px. Wheel 48 px a notch.
- **A `.Tooltip` blocks the mouse**, since it reacts to the mouse.
- **`InputScript`** moves the tape out of `Super.Testing` into `Super`, and `ScriptedInput` builds on it. `IGame.Script(name)` supplies scenes.

## Review Focus

1. A tap inside one tick on a panel: neither `Pressed`, `Down` nor the later `Released` reach the game. Test in Task 5.
2. The pressed or dragged view leaves the tree mid-gesture: no crash, no callback. Test in Task 5 and Task 7.
3. Content shrinks while scrolled to the end, or the window resizes: offset clamps, no blank space. Test in Task 6.
4. `Input.CaptureMouse` during mouse look: the interface takes nothing, so looking around over a panel works. Test in Task 5.
5. A press before anything was laid out, on the very first tick: goes to the game, no crash. Test in Task 5.
