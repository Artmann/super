# Input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keyboard, mouse and gamepad input for Super as a per-tick snapshot (`Input`) with a typed action layer (`Actions<TControl>`) on top, scriptable in headless tests.

**Architecture:** `Input` is an injected service that owns a pending event buffer and a frozen per-tick snapshot. The window feeds the buffer from GLFW callbacks; `ScriptedInput` in `Super.Testing` feeds it from a tick-stamped tape. `GameHost` rolls the buffer into the snapshot before each tick and makes `Input` unreadable during `Draw` and `Ui`. `Actions<TControl>` listens to each roll, evaluates its bindings, and keeps last tick's state for edges.

**Tech Stack:** .NET 10, Silk.NET.GLFW (already referenced), xunit, Microsoft.Extensions.DependencyInjection.

**Spec:** `docs/superpowers/specs/2026-11-01-input-design.md`

## Global Constraints

- Braces on every `if`, `while`, `for`, `foreach`, including one-liners (project CLAUDE.md).
- Conventional commits (`feat:`, `fix:`, `docs:`, `chore:`), no Claude as author, no Co-Authored-By.
- No per-tick allocations once running. `SpinningCubeTests.Running_the_game_allocates_nothing_per_frame` must keep passing after ColorCube uses input.
- No static or global input state; everything hangs off the injected `Input`.
- Games never reference Silk.NET: all input enums are Super's own.
- Never capture the desktop when checking the window. Use `--screenshot`.
- Doc comments in the existing plain style (`/// <summary>` one or two sentences, no jargon).

## Review Focus

1. **Key repeat.** Holding a key makes GLFW send repeat events; they must not count as new presses. Test in Task 1.
2. **Unknown key codes.** GLFW sends -1 for keys it doesn't know; the window must drop them rather than index an array. Test in Task 4 (unit test on the mapping helper).
3. **Reading in `Load`.** `Load` runs before any tick, so there is no snapshot; a read there throws with the same message. Binding in `Load` is fine. Test in Task 3.
4. **Gamepad unplugged mid-game.** Buttons that were down must report Released once and sticks go to zero, not freeze. Test in Task 1.
5. **Composite with opposite keys held.** W and S together give a zero vector, not NaN from normalizing zero. Test in Task 2.

**Interfaces:**
- Produces, public on `Input`: `bool Down(Key)`, `Pressed(Key)`, `Released(Key)`, same three for `MouseButton` and `GamepadButton`; `Vector2 MousePosition`, `Vector2 MouseDelta`, `float Scroll`, `string Typed`, `Vector2 Stick(GamepadStick)`, `float Trigger(GamepadTrigger)`, `bool GamepadConnected`, `float DeadZone { get; set; }` default `0.2f`, `bool CaptureMouse { get; set; }`.
- Produces, internal on `Input` (fed by the window in Task 4 and the tape in Task 3): `void KeyDown(Key)`, `KeyUp(Key)`, `MouseButtonDown(MouseButton)`, `MouseButtonUp(MouseButton)`, `MouseMoved(Vector2 position)`, `Scrolled(float notches)`, `TypedCharacter(char)`, `Gamepad(bool connected, ReadOnlySpan<float> axes, ReadOnlySpan<bool> buttons)` (axes in GLFW order LX, LY, RX, RY, LT, RT; GLFW's raw ranges), `void Roll()`, `bool Readable { get; set; }`, `int RollCount { get; }`, `void Listen(IInputListener)`.
- Produces, internal: `interface IInputListener { void Rolled(); }` called at the end of every `Roll()`.
- Enum values: `Key` uses GLFW's key codes as its values (Space = 32, A = 65, W = 87, Escape = 256, arrows 262..265, F1 = 290, shifts 340/344, and the rest), so the window maps with a cast. `MouseButton` Left = 0, Right = 1, Middle = 2 up to 7. `GamepadButton` in GLFW gamepad order: South, East, West, North, LeftBumper, RightBumper, Back, Start, Guide, LeftStick, RightStick, DPadUp, DPadRight, DPadDown, DPadLeft. `GamepadStick` Left, Right. `GamepadTrigger` Left, Right.

Snapshot rules (from the spec), per button:
- `Pressed` = at least one down event since the last roll.
- Physically down at roll → `Down`; `Released` = at least one up event since the last roll.
- Physically up at roll with a down event in the window (a tap) → `Down` and `Pressed` true now, `Released` true on the next roll, not this one.
- Physically up, no down event → `Down` false, `Released` = up event seen or a tap is pending release.
- A down event while already physically down (repeat) is ignored.
- `MouseDelta` and `Scroll` are sums since the last roll; `MousePosition` is the latest; `Typed` is the characters since the last roll, `string.Empty` when none (no allocation then).
- `Stick` flips GLFW's Y so forward is positive, applies a radial dead zone: length below `DeadZone` gives zero, otherwise rescaled so `DeadZone` maps to 0 and 1 to 1, clamped to length 1. `Trigger` maps GLFW's -1..1 to 0..1.
- `Gamepad(connected: false, ...)` behaves as all buttons up and all axes centred.
- Every public read throws `InvalidOperationException("Input can only be read in Update. Draw and Ui describe state, so they can't look at input.")` when `Readable` is false. Reads are readable only after the host sets the flag (Task 3); a bare `new Input()` in a unit test sets `Readable = true` itself.

### Task 2: Bindings and `Actions<TControl>`

**Files:**
- Create: `src/Super/Input/Binding.cs` (`Binding`, `Keys`, `Mouse`)
- Create: `src/Super/Input/Actions.cs`
- Test: `tests/Super.Tests/Input/ActionsTests.cs`

**Interfaces:**
- Consumes: `Input` from Task 1, `IInputListener`.
- Produces: `public readonly record struct Binding` with `float Scale` (default 1), `Binding Scaled(float scale)`, implicit conversions from `Key`, `MouseButton`, `GamepadButton`, `GamepadStick`, `GamepadTrigger`; statics `Binding.Axis(Binding negative, Binding positive)` (operands must be a key, mouse button, gamepad button or trigger; anything else throws `ArgumentException`), `Binding.Composite(Binding up, Binding down, Binding left, Binding right)` (same operand rule), `Binding.MouseDelta`, `Binding.MouseScroll`. `public static class Keys { Binding WASD; Binding Arrows; }`. `public static class Mouse { Binding Delta; Binding Scroll; }`. `Keys.WASD` is `Composite(W, S, A, D)`; `Arrows` is `Composite(Up, Down, Left, Right)`.
- Produces: `public sealed class Actions<TControl> where TControl : struct, Enum` with constructor `Actions(Input input)`; `void Bind(TControl control, params Binding[] bindings)`; `void Unbind(TControl control)`; `IReadOnlyList<Binding> Bindings(TControl control)`; `bool Down/Pressed/Released(TControl)`; `float Value(TControl)`; `Vector2 Vector(TControl)`; internal `void Override(TControl control, Vector2 vector, bool button)` and `void ClearOverride(TControl control)`.
- Binding payload: a kind enum plus up to four `(SourceKind, int code)` pairs, no references, so `Binding` is a plain value and the bindings list is the only heap object. Scalar read of a `(SourceKind, code)` pair: key, mouse button, gamepad button give 1 while down; trigger gives its 0..1 value.
- Evaluation per control, on `Rolled()` (Actions registers itself with `input.Listen(this)` in its constructor): clamped vectors are summed and clamped to length 1; `MouseDelta` and `MouseScroll` contributions (times their `Scale`) are summed separately and added on top. `Composite` gives `(right - left, up - down)`, normalized only when its length is above 1. Every contribution is multiplied by its binding's `Scale`. `Value` is the result's length, or 1 if any plain button binding is down. `Down` is `Value > 0.5f`. `Pressed`/`Released` compare `Down` with the previous roll. An active override replaces the evaluation: `button ? 1 : vector.Length()` for `Value`, the vector for `Vector`.
- `TControl` to index: `Unsafe.As<TControl, int>(ref control)`; the constructor throws `ArgumentException` when `Unsafe.SizeOf<TControl>() != sizeof(int)`, and sizes arrays from `Enum.GetValues<TControl>()` max + 1.
- Reads go through `Input.Readable`: every public read calls an internal `input.CheckReadable()`.

**Interfaces:**
- Consumes: `Input.Roll()`, `Input.Readable`, the internal feed methods, `Actions<T>.Override/ClearOverride`.
- `GameHost`: `services.AddSingleton<Input>()` and `services.AddSingleton(typeof(Actions<>))` before `configure`; public `Input Input { get; }`; internal `T GetService<T>() where T : notnull` over `_services`. `Tick()` becomes: `Input.Roll(); Input.Readable = true;` then hooks, then `Game.Update`, then `Input.Readable = false; Time.Tick++`. `Readable` starts false, so `Load`, `Draw` and `Ui` all throw on a read.
- Produces: `public sealed class ScriptedInput` (constructed internally with the host) with `Press(Key)`, `Hold(Key)`, `Release(Key)`, same for `MouseButton` and `GamepadButton`, `MoveMouse(Vector2)`, `Click(MouseButton button, Vector2? at = null)`, `Scroll(float notches)`, `Type(string text)`, `Stick(GamepadStick stick, Vector2 value)` (held until set again; writes raw axes `(value.X, -value.Y)`, so the dead zone applies as it would to a real pad), `Trigger(GamepadTrigger, float)`, and generic `Press<TControl>(TControl)`, `Hold<TControl>(TControl)`, `Hold<TControl>(TControl, Vector2)`, `Release<TControl>(TControl)` where `TControl : struct, Enum`, resolving `Actions<TControl>` through `GameHost.GetService`.
- Tape: a `List<(long Tick, Action<Input> Apply)>` is fine here because tests allocate freely; entries are stamped with the tick they land on. Calls made between `Ticks` land on the next tick (`host.Time.Tick`). `Press` adds a down and an up on tick N (a tap); `Press<TControl>` adds an override on N and a clear on N + 1. `Hold` adds a down on N; `Release` an up on N. `HeadlessRun.Ticks` calls `Input.Play(_host.Time.Tick)` before `_host.Tick()`, which applies and removes every entry stamped with that tick.
- `HeadlessRun<TGame>` gains `public ScriptedInput Input { get; }`.

### Task 4: The window feeds input from GLFW

**Interfaces:**
- Consumes: `Input` feed methods from Task 1, `host.Input`.
- Produces: `internal static class GlfwInput` with `static bool TryMapKey(int glfwKey, out Key key)` (false for -1 and any value outside the enum), `static Vector2 ToFramebuffer(double x, double y, int windowWidth, int windowHeight, int framebufferWidth, int framebufferHeight)` (scales window coordinates into the framebuffer space the interface lays out in; returns the input unchanged when either window size is 0).
- `GameWindow` registers key, mouse button, cursor position, scroll and char callbacks once per host run (it needs the `Input` instance, so registration happens at the start of `Run` and the delegates are kept in fields so the GC can't collect them). The key callback ignores `InputAction.Repeat`. Before each `host.Tick()` in `Run`, it polls the first joystick for which `JoystickIsGamepad` is true, reads `GetGamepadState`, and calls `input.Gamepad(connected, axes, buttons)`; when none, `input.Gamepad(false, default, default)`. After the ticks, it applies `input.CaptureMouse` with `SetInputMode(CursorStateAttribute.Cursor, CursorModeValue.CursorDisabled / CursorNormal)` only when the value changed since the last frame. Screenshot, record and profile paths don't register callbacks; the game sees no input there, which keeps `--screenshot` identical to before.
- Use `_glfw.GetWindowSize` and `GetFramebufferSize` at the time of the cursor callback for the scale.
